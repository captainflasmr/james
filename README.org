#+title: james
#+language: en
#+options: ':t toc:nil num:nil
#+startup: showall

A very minimal, Emacs/MicroEmacs-inspired text editor, written in Zig on top of [[https://github.com/rockorager/libvaxis][libvaxis]]. This is a starting point, not a finished editor — see Roadmap below.

* Requirements

- Zig *0.16.0* exactly (pinned in =build.zig.zon=; libvaxis tracks this version closely and older/newer Zig will likely fail to compile it)

* Build & run

#+begin_src sh
zig build run -- path/to/file.txt [more-files...]
#+end_src

Every filename given on the command line opens as its own buffer; the first one is shown initially. With no filenames, james starts on the home screen in a three-pane layout: the welcome screen left (full height), the =scratch.txt= buffer top right, and a dired of the current directory bottom right. The welcome screen shows the version block centered under the banner — the latest version, its release date, the time the binary was built, and the most recent change, baked in at build time so it appears however james is launched — followed by the full keybinding reference, grouped by prefix and context. =scratch.txt= is a real file in the current directory — created on first startup if missing, never truncated — so it saves and prompts exactly like any other buffer. =C-x d= from there browses files, or use =C-x C-f= / =C-x b=. First run will fetch libvaxis automatically. To fetch dependencies ahead of time (e.g. for an offline build later): =zig build --fetch=.

A plain =zig build= already produces a ReleaseSmall, stripped binary (james is meant to be run, not debugged). If you do need to debug: =zig build -Doptimize=Debug -Dstrip=false=.

* Cross-compiling

No extra toolchains, no Docker. Confirmed working targets:

#+begin_src sh
zig build -Dtarget=x86_64-windows -Doptimize=ReleaseSmall
zig build -Dtarget=aarch64-macos -Doptimize=ReleaseSmall
zig build -Dtarget=x86_64-linux-musl -Doptimize=ReleaseSmall
zig build   # native, already ReleaseSmall and stripped
#+end_src

Binaries land in =zig-out/bin/= for native builds; a cross-compiled preset goes to its own folder (=zig-out/windows/=, =zig-out/macos/=, =zig-out/linux/=) so it never overwrites the native binary — running one of those on the wrong host fails with an "exec format error". Use =-p some/dir= to override the output folder.

The path resolution mirrors the elisp's =system-type= checks exactly: on Windows =M-l d= consults =%USERPROFILE%\Downloads= (with the =~/Downloads= fallback), =M-l g= consults =%APPDATA%= (with the =~/AppData/Roaming= fallback), and =M-l h= consults =%USERPROFILE%=; elsewhere they are plain =~/Downloads=, =~/.config= and =~=. A jump that can't be opened (a missing =~/bin=, say) just leaves the window alone, and every jump is recorded in the winner-mode history, so =C-c j= steps back out of it.

Tabs (a numbered tab set in the spirit of Emacs =tab-bar-mode=, without per-tab buffer association): =M-l == opens a new tab at the right end of the set — a single window on the buffer the cursor is in — =M-l -= closes the current one, =M-1=..=M-9= selects a tab by number, and =M-i= / =M-u= step to the next / previous tab (wrapping). Each tab is an independent window layout over the shared buffer list. The tab bar — one numbered block per tab, the active one highlighted — appears at the top of the screen only once a second tab exists; with a single tab the screen is exactly as before. Window history does not cross tabs.

While searching: type to extend the query, =C-s=/=C-r= again jumps to the next/previous match, Backspace shrinks the query, =C-g= cancels back to where you started, and Enter (or any other key) confirms and leaves the cursor at the match. A search with no match shows "Failing I-search" and stops moving the cursor until you backspace back to something that matches. The last search string is remembered, like Emacs: a fresh =C-s= (or =C-r=) with an empty query repeats the previous search from the cursor — jump to the top with =M-<= and press =C-s= to find it again from the start — and typing a new term replaces the remembered one instead of gluing onto it. =M-c= during a search turns the query into an occur (my/occur-from-isearch).

If the buffer has unsaved changes, =C-x C-c= asks "Save file ... before exiting?" on the status line: =y= saves and quits, =n= quits without saving, and =C-g= (or Escape) cancels the quit and returns to editing. Any other key is ignored while the prompt is up, rather than risk a stray keystroke accidentally choosing for you.

Consecutive =C-k=/=C-x C-k=/=M-w= presses append to the same kill instead of overwriting it, same as real Emacs — typing or moving the cursor in between starts a fresh kill. Consecutive kills are joined with a newline (killing =abc= then =def= yanks as =abc\n def=, not a merged =abcdef=). The kill ring is a real ring, shared across all open buffers, holding the last sixty kills: =C-y= yanks the most recent, and =M-y= cycles back through the older ones, replacing the previous yank in place (one undo step for the whole run). Every kill or copy is also mirrored onto the system clipboard (OSC 52), so text you kill in james can be pasted into any other application — and over ssh too, since the terminal forwards the sequence; terminals without OSC 52 support just ignore it. The other direction works the same way: =C-y= with an empty kill ring pastes the system clipboard into the buffer. Once a mark is set, the region between mark and point is shown in reverse video as you move the cursor, and the highlight clears automatically once you kill, copy, or otherwise drop the mark.

Undo (=C-x u=) restores whole-buffer snapshots taken before each edit, and coalesces a run of the same kind of edit (a burst of typing, a run of backspaces) into a single step, so undoing a word you just typed is one keypress, not one per character. Switching to a different kind of edit — or moving the cursor — starts a new undo step. There's no redo yet; undo is a one-way trip back through history, and it doesn't (yet) clear the =[modified]= flag even if it lands you back on the exact text you loaded. Undo history, the mark, cursor position, and the dirty flag are all separate per buffer; only the kill ring is shared.

=C-x C-b= opens the =*Ibuffer*=, Emacs's ibuffer: a persistent buffer listing every open buffer in a table — the =MRL= mark / read-only / lock column, then the name, size, mode and filename columns, with a footer of the total count, size and file count (=3 buffers 6588 1 files, no processes=). Modes read like Emacs's: =Dired by name= (and by size / date / extension, following the dired's sort), =Grep= / =Files= / =Occur= / =Home= for the special buffers, =Fundamental= for a plain file; read-only buffers (direds and the specials) show =%= in the R column, long names elide with =...=, and the listing defaults to a name sort with the starred buffers first (=s= toggles to the buffer-list order, what the =C-x b= picker shows). Rows truncate by default, like the =*grep*= / =*files*= / =*occur*= results — one buffer per line, however long the name (=M-z= toggles soft wrap). It behaves like any buffer — it stays open in the list, =C-x o= / =C-x b= move around it, and the listing re-reads itself whenever the buffer list changes, so a row can never be stale. In it: =n= / =p= (arrows too) move, Enter opens the row's buffer in the window (the =*Ibuffer*= stays open, like a dired), =m= / =u= mark and unmark rows with a =*= in the M column, =U= unmarks everything, =t= toggles all the marks, =X= kills the marked buffers (marked file buffers with unsaved changes ask first, like =C-x k=: =y= kills them without saving, =n= keeps them and reports =Modified buffers kept=, =C-g= cancels; the kills are saved in window history), =g= re-reads the listing (Emacs =revert-buffer=), =q= / =C-g= closes, and =C-s= / =C-r= search the table like any buffer. It is the persistent sibling of the =C-x b= picker: that is the transient quick-access list, this is the full listing with marks and operations.

=C-x r l= opens the =*Bookmarks*=, the bookmark list in a buffer (Emacs =bookmark-bmenu-list=): a persistent table with a =Name= column — the bookmark's name, 20 wide, long names eliding with =...= — and the bookmarked path taking the rest of the line, under a header and dashes ruler, with a footer of the total count (=2 bookmarks=, like the ibuffer's summary line). It behaves like any buffer — it stays open in the list, =C-x o= / =C-x b= move around it, and the listing re-reads itself whenever a bookmark is set or reloaded, so a row can never be stale. In it: =n= / =p= (arrows too) move, Enter jumps to the row's bookmark in this window (the =*Bookmarks*= stays open, like a dired), =g= re-reads the listing (Emacs =revert-buffer=), =q= / =C-g= closes, and =C-s= / =C-r= search the table like any buffer. It is the persistent sibling of the =C-c o= / =M-l o= bookmark picker: that is the transient quick-access list with fuzzy filtering, this is the full listing you can sit in and inspect.

=C-x b= shows a picker list of every open buffer — file buffers, direds, the home screen — one per row, exactly like the bookmark list and the recent-files list (=M-l l= opens the same picker over the files james has opened, remembered newest-first in =~/.james-recent= and capped at forty, mirroring the author's Emacs =my/fido-recentf=): typing filters the rows as you go (an Emacs partial-completion match: each space-separated group of the query must appear as a contiguous case-insensitive substring, in order — "req b" matches "revert-buffer" — earliest matches first), arrows / =C-n= / =C-p= move the selection, =C-s= / =C-r= incremental-search the rows (the selection follows the match, Enter confirms it), Enter opens the selected buffer / bookmark / recent file, Backspace shortens the filter, and =C-g= / Esc clear the filter first, then close. The filter's matched characters highlight in each row as you type. The modeline shows the filter and the visible count (=Buffers (2/3) filter: sc=). The cursor starts on the current buffer, and the picker docks at the bottom of the display icomplete-vertical-style — the windows shrink up to make room, their modelines sitting just above the candidate list, the current candidate is highlighted in reverse video, and the typed filter sits in a prompt row beneath the candidates with the cursor at its end — so the buffer stays visible above while picking. =C-x C-f= prompts for a path in the current window's modeline (the window layout doesn't change), prefilled with the current buffer's directory (a dired's own while browsing) — always absolute and ending in a separator, so typing a bare file name opens it right there: type a path and Enter switches to it if it's already open (matched by exact path, whitespace-trimmed), or loads and opens it fresh — a directory path opens a dired buffer for it. Real Emacs splits these two commands the same way (=C-x C-f= opens by path, =C-x b= switches by buffer name). =C-g=/Escape cancels the prompt. When more than one buffer is open, the status line shows =(current/total)= so it's visible at a glance. =C-x k= kills (closes) the current buffer — a file buffer, a dired, or the home screen: a modified file buffer asks first (=y= saves and kills, =n= kills without saving, =C-g= / Escape cancels), the last buffer is never killed, and any window that showed the killed buffer falls back to the next one.

=C-x d= opens a directory browser (dired) rooted at the directory of the current buffer's file (or =.= if the buffer has no file). A dired is an ordinary buffer, exactly like Emacs: it lives in the buffer list (so several directories can be open at once), shows in any window, and =C-x o= / =C-x b= move around it freely. Opening a file from dired shows it in the window and leaves the dired buffer open; =C-x b= with its path brings it back. While in a dired buffer: =n= / =C-n= / ↓ and =p= / =C-p= / ↑ move the selection, =C= copies the selected entry (target prompt prefilled with the name), =D= deletes it after a y/n confirmation, =W= opens it with the system's default handler (=xdg-open= on Linux/BSD, =open= on macOS, cmd's =start= on Windows), =^= / =M-e= goes to the parent directory, Enter or =f= descends into a directory (opening a new dired buffer for it) or opens the selected file, =C-s= / =C-r= incremental-search the file names (the selection follows the match), =g= re-reads the directory (Emacs =revert-buffer=, keeping the selection), and =q= / =C-g= / =C-c C-k= closes the dired buffer. The listing ends with the trailing newline an Emacs dired has: =M->= (or =n= past the last entry) rests the selection on the empty final line, and copies of the listing (=C-c b=, =C-x h= + =M-w=) carry the final line break. The listing re-sorts on the digit keys, mirroring the ls flags: =3= by size (largest first, =ls -S=), =4= by modification time (newest first, =ls -t=), =5= by name, =6= by extension (=ls -X=), and =s= toggles between name and date (dired-sort-toggle-or-edit); the selection moves to the first real entry, and the chosen order is kept when the listing refreshes. Entries are sorted with =..= first; directories and files are interleaved rather than grouped, directories are shown with a trailing =/=, and hidden (dot) files are listed too. Each entry is prefixed with an =ls -al= style metadata line: permissions (rwx bits on Unix, read-only/writable on Windows), size, and modification time — =(= hides that metadata (Emacs =dired-hide-details-mode=), leaving just the names, with =Dired: <path> (Hide-Details)= in the modeline while hidden. The listing starts with the full directory path on its first line (the classic dired header line), and the modeline shows the same absolute path (=Dired: <path>=) — whichever relative path (say =.=) opened the directory, the header and modeline name the actual directory, with =.= and =..= components resolved.

The modeline is a bar that spans the full width of its window, like Emacs's mode line: reverse video in the current window and dimmed in the others, whether split or single-window. A prompt's label — =Find file:=, =I-search:=, the dired copy / rename / delete prompts and the like — renders bold, so it stands out from the typed text. Between the windows of a split, a thin box-drawing line marks the boundary (a vertical =│= between side-by-side panes, a horizontal ==─== between stacked ones), with nested splits joining cleanly.

=C-c f= finds files the same way grep searches content, into a persistent =*files*= buffer that works exactly like =*grep*=: the current directory's files — the dired's own while browsing, the file's directory otherwise — are listed by ripgrep =--files= when available, falling back to =find -type f= on POSIX and Windows' =dir /s /b= (Windows' built-in =find= searches file *contents*, the DOS-era grep, so =dir= is the name lister there). The buffer stays open — =C-x b= returns to it, window history (=C-c j= / =C-c k=) steps through its layouts, and it can sit in any window like any other buffer. =n= / =p= (and arrows / =C-n= / =C-p=) step through the files, Enter opens the one under point in another window — splitting to the right when it's the only window, reusing the window last used for a jump otherwise — =F= toggles follow mode so stepping opens each file automatically, and =g= re-runs the find. Typing filters the list (partial-completion, matched against the full path, the matched characters highlighting in each row), Backspace shortens the filter, =C-s= / =C-r= search the rows, and =C-g= / Esc clear the filter first, then close.

=C-c g= greps the current directory, mirroring the author's Emacs =my/grep=: a modeline prompt asks for the search term (prefilled with the word at point), and ripgrep runs over the dired's directory while browsing, or the current file's directory otherwise — falling back to =grep -rni= on POSIX and =findstr /s /n /i= on Windows, which has shipped with every Windows since NT 4, so the fallback always exists. The matches open in a =*grep*= buffer (always truncated, one result per row): =n= / =p= move between them, Enter opens the match in another window — the grep buffer splits to the right when it's the only window, otherwise the window last used for a jump (or the next one over) is replaced — and that window is reused, so n/p + Enter steps through the matches without the layout changing. =F= toggles follow mode (the modeline shows =[follow]=): while it's on, every n/p (or arrow / =C-n= / =C-p=) move opens the match under point in that same window automatically, focus staying on the grep buffer — pure stepping. Each jump also flashes a transient highlight of the grepped term in the target file (like Emacs's =next-error-highlight=), so the match is easy to spot; it fades on its own within a couple of seconds. =g= re-runs the search with the term prefilled, =q= / =C-g= closes, and =C-s= / =C-r= search the results. The term is remembered across re-runs.

=M-c= is occur, the buffer's sibling of grep: every line of the current buffer matching a term lands in a persistent =*occur*= buffer that behaves exactly like =*grep*= — one row per match as =line: text=, the term ASCII case-insensitive like isearch. =n= / =p= move between the matches, Enter jumps to the match in the source file (the occur buffer splits to the right when it's the only window, and the window used for one jump is reused for the next), =F= follows so stepping opens each match automatically, =g= re-runs over the source file picking up any edits since, and =q= / =C-g= closes. The prompt is prefilled with the word at point, and pressing =M-c= during a search (=C-s= / =C-r=) starts from the search string (my/occur-from-isearch); jumps flash the term in the source like a grep jump. Occur is editing-only: results buffers and direds have no text to scan, and the home screen has no file to jump back to.

=C-x j= (or =C-x c=) drops the whole editor out of the way and hands the terminal to a real shell (=$SHELL=, or =/bin/sh=): the alternate screen is left and the terminal restored to its normal mode, so anything that works in your terminal works here — full-screen programs included. =exit= (or =C-d=) comes straight back to the editor, and so does =C-z=, which merely suspends the shell; the next =C-x j= (or =C-x c=) resumes that same session, working directory and all. It's the same suspend-and-swap trick as Emacs's =C-z= (suspend-frame), on one key. On Windows the same key drops into a shell too (=$SHELL=, =COMSPEC=, or =cmd.exe=) with the console restored to its normal mode — but the Windows console has no job-control stop, so returning is =exit= only. =C-x T= is the sibling that leaves the editor alone: instead of taking over this terminal it opens a *new* native terminal window in the same context directory — Windows Terminal where installed (a new =cmd.exe= window otherwise) on Windows, Terminal.app on macOS, the first installed desktop emulator on Linux/BSD (gnome-terminal, konsole, xfce4-terminal, kitty, alacritty, wezterm, then the generic =x-terminal-emulator= / =xterm=) — and =C-x E= reveals the current context in the native file manager instead: the selected entry while browsing a dired (a file opens its folder, selected in Finder, Nautilus, Dolphin, Nemo and Caja, plainly elsewhere), the file itself in a file buffer, the working directory otherwise.

* Architecture

- =src/Buffer.zig= — all text state: lines, cursor, load/save, edit and movement operations. Knows nothing about the terminal, and nothing about any *other* buffer — each open file is a fully independent instance.
- =src/Dired.zig= — all directory-browser state: the current path, the entry list, the selection, and navigation (open, reload, move, go to parent, choose). Knows nothing about the terminal or about buffers, the same split as =Buffer.zig=.
- =src/main.zig= — the only platform-facing file: sets up the terminal via vaxis, runs the event loop, maps keys to =Buffer= calls, renders.

Keeping that split matters: it's the same portability discipline MicroEmacs used in the 1980s to run unmodified across CP/M, MS-DOS, VMS and Unix. Everything except =main.zig='s terminal setup should port to any future front end (a different TUI library, or eventually a GUI) unchanged.

Open buffers live in =main.zig= as =std.ArrayList(*Buffer)= — a list of *pointers* to individually heap-allocated buffers, not a list of buffers by value. That's deliberate: appending to the list (opening a new file) can reallocate the list's own backing array, which would silently invalidate a plain =*Buffer= pointer taken from it earlier. A pointer to an independently allocated =Buffer= stays valid regardless of what the list around it does. The kill ring is the one piece of state that lives above the buffer list entirely, shared by every buffer, matching real Emacs.

* Roadmap

1. +*Kill ring + yank*+ — done (=C-space=, =C-k=, =C-x C-k=, =M-w=, =C-y=). =Buffer.mark= is a plain snapshot, not a self-adjusting marker, so it can go stale if you edit the buffer between setting mark and using the region — acceptable for now, worth revisiting if it bites you.
2. +*Undo*+ — done (=C-x u=), whole-buffer snapshots with same-kind coalescing. Adding redo would mean pushing undone states onto a second stack that gets cleared on any new edit — a natural follow-up, not done yet.
3. +*Incremental search*+ — done (=C-s= / =C-r=). Search never crosses a line boundary and wraps around the buffer when it runs off either end. The =isearch_active= branch at the top of the key-dispatch loop in =main.zig= is the "mode" plumbing mentioned above — when =M-x= arrives, it's a second branch of the same shape, not a redesign.
4. +Unsaved-changes confirmation on =C-x C-c=+ — done. A save that fails (disk full, permissions, etc.) is still silently swallowed either way, same as =C-x C-s= today — worth real error reporting eventually.
5. +*Multiple buffers*+ — done (=C-x b=, =C-x C-f=). Every open buffer is its own heap-allocated =Buffer=; only the kill ring is shared. =C-x k= kills (closes) the current buffer — a modified file buffer asks first (y saves and kills, n kills without saving, =C-g= cancels), the last buffer is never killed, and any window that showed the killed buffer falls back to the next one.
6. +*Directory browser (dired)*+ — done (=C-x d=). =src/Dired.zig= holds all directory state with no knowledge of the terminal or of buffers, the same split as =Buffer.zig=; =main.zig= just wires keys and rendering. =n= / =p= move, =^= goes to the parent, Enter opens a file (reusing the =C-x b= / =C-x C-f= open-or-switch path) or descends into a directory, =C-g= / =q= leaves. =m= marks the entry under the cursor and steps down, =u= unmarks one, =U= unmarks everything, =t= toggles the whole set (nothing marked marks everything, otherwise the marks invert), and =%= =m= (Emacs =dired-mark-files-regexp=) prompts for a regexp and marks every entry whose name matches it — the prompt takes a small strict-Emacs-syntax regexp (=^=, =$=, =.=, =[...]= classes, =*= =+= =?=, =\(...\)= groups and =\\|= alternation — a bare =(= =)= =|= is a literal, so names containing them match as-is — plus =\\d= =\\w= =\\s= and literal escapes), and the modeline reports how many were marked — marked entries show a =*= in column 0, and =C= copies, =R= renames (moves) and =D= deletes every marked entry at once. Copy and rename each default to the directory of another dired window when one exists (Emacs =dired-dwim-target=): with a two-window split — a source dired on one side, a destination on the other — =C= or =R= then Enter copies or moves the marked entries (or the selected one, when nothing is marked) into the other pane's directory, whichever side holds the cursor. =+= creates a directory and =_= an empty file in the current directory (Emacs =dired-create-directory=), leaving the selection on the new entry. Entries sort with =..= first then case-insensitive; directories and files are interleaved (not grouped) and directories get a trailing =/=. =Dired.parentOf= doesn't canonicalise — once =dirname= can't go further up a relative path it just accumulates literal =..= components, which the OS resolves fine; it returns null only at the absolute filesystem root.
7. Config: start with a plain keymap-override file, consider embedded Lua later if you want real elisp-like programmability.
