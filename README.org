#+title: james
#+language: en
#+options: ':t toc:nil num:nil
#+startup: showall

A very minimal, Emacs/MicroEmacs-inspired text editor, written in Zig on top of [[https://github.com/rockorager/libvaxis][libvaxis]]. This is a starting point, not a finished editor — see Roadmap below.

* Requirements

- Zig *0.16.0* exactly (pinned in =build.zig.zon=; libvaxis tracks this version closely and older/newer Zig will likely fail to compile it)

* Build & run

#+begin_src sh
zig build run -- path/to/file.txt [more-files...]
#+end_src

Every filename given on the command line opens as its own buffer; the first one is shown initially. With no filenames, james starts on a home screen with a keybinding cheat sheet — =C-x d= from there browses files, or use =C-x C-f= / =C-x b=. First run will fetch libvaxis automatically. To fetch dependencies ahead of time (e.g. for an offline build later): =zig build --fetch=.

A plain =zig build= already produces a ReleaseSmall, stripped binary (james is meant to be run, not debugged). If you do need to debug: =zig build -Doptimize=Debug -Dstrip=false=.

* Cross-compiling

No extra toolchains, no Docker. Confirmed working targets:

#+begin_src sh
zig build -Dtarget=x86_64-windows -Doptimize=ReleaseSmall
zig build -Dtarget=aarch64-macos -Doptimize=ReleaseSmall
zig build -Dtarget=x86_64-linux-musl -Doptimize=ReleaseSmall
zig build   # native, already ReleaseSmall and stripped
#+end_src

Binaries land in =zig-out/bin/= for native builds; a cross-compiled preset goes to its own folder (=zig-out/windows/=, =zig-out/macos/=, =zig-out/linux/=) so it never overwrites the native binary — running one of those on the wrong host fails with an "exec format error". Use =-p some/dir= to override the output folder.

Buffer keys:

| Keys | Action |
|---+---|
| =M-<= / =M->= | beginning / end of buffer |
| =M-j= / =M-k= | 5 lines down / up |
| =C-x C-k= | kill region (alias of =C-w=) |

While searching: type to extend the query, =C-s=/=C-r= again jumps to the next/previous match, Backspace shrinks the query, =C-g= cancels back to where you started, and Enter (or any other key) confirms and leaves the cursor at the match. A search with no match shows "Failing I-search" and stops moving the cursor until you backspace back to something that matches.

If the buffer has unsaved changes, =C-x C-c= asks "Save file ... before exiting?" on the status line: =y= saves and quits, =n= quits without saving, and =C-g= (or Escape) cancels the quit and returns to editing. Any other key is ignored while the prompt is up, rather than risk a stray keystroke accidentally choosing for you.

Consecutive =C-k=/=C-w=/=M-w= presses append to the same kill instead of overwriting it, same as real Emacs — typing or moving the cursor in between starts a fresh kill. The kill ring is shared across all open buffers, so you can kill text in one file and yank it into another. Once a mark is set, the region between mark and point is shown in reverse video as you move the cursor, and the highlight clears automatically once you kill, copy, or otherwise drop the mark.

Undo (=C-x u=) restores whole-buffer snapshots taken before each edit, and coalesces a run of the same kind of edit (a burst of typing, a run of backspaces) into a single step, so undoing a word you just typed is one keypress, not one per character. Switching to a different kind of edit — or moving the cursor — starts a new undo step. There's no redo yet; undo is a one-way trip back through history, and it doesn't (yet) clear the =[modified]= flag even if it lands you back on the exact text you loaded. Undo history, the mark, cursor position, and the dirty flag are all separate per buffer; only the kill ring is shared.

=C-x b= shows a picker list of every open buffer — file buffers, direds, the home screen — one per row, exactly like the bookmark list: n/p (or arrows) move, Enter switches to the selected buffer, q or =C-g= closes. The cursor starts on the current buffer, and the picker takes over the whole screen for a moment without touching the window layout. =C-x C-f= keeps the old prompt: type a path and Enter switches to it if it's already open (matched by exact path, whitespace-trimmed), or loads and opens it fresh — a directory path opens a dired buffer for it. Real Emacs splits these two commands the same way (=C-x C-f= opens by path, =C-x b= switches by buffer name). =C-g=/Escape cancels the prompt. When more than one buffer is open, the status line shows =(current/total)= so it's visible at a glance. There's no way to close a file buffer yet (=C-x k= in real Emacs) — a natural next step.

=C-x d= opens a directory browser (dired) rooted at the directory of the current buffer's file (or =.= if the buffer has no file). A dired is an ordinary buffer, exactly like Emacs: it lives in the buffer list (so several directories can be open at once), shows in any window, and =C-x o= / =C-x b= move around it freely. Opening a file from dired shows it in the window and leaves the dired buffer open; =C-x b= with its path brings it back. While in a dired buffer: =n= / =C-n= / ↓ and =p= / =C-p= / ↑ move the selection, =C= copies the selected entry (target prompt prefilled with the name), =D= deletes it after a y/n confirmation, =^= / =M-e= goes to the parent directory, Enter or =f= descends into a directory (opening a new dired buffer for it) or opens the selected file, =C-s= / =C-r= incremental-search the file names (the selection follows the match), and =q= / =C-g= / =C-c C-k= closes the dired buffer. Entries are sorted with =..= first, then case-insensitive by name; directories and files are interleaved rather than grouped, directories are shown with a trailing =/=, and hidden (dot) files are listed too. Each entry is prefixed with an =ls -al= style metadata line: permissions (rwx bits on Unix, read-only/writable on Windows), size, and modification time. The modeline shows =Dired: <path>= while browsing.

The modeline is a bar that spans the full width of its window, like Emacs's mode line: reverse video in the current window and dimmed in the others, whether split or single-window. Between the windows of a split, a thin box-drawing line marks the boundary (a vertical =│= between side-by-side panes, a horizontal ==─== between stacked ones), with nested splits joining cleanly.

* Architecture

- =src/Buffer.zig= — all text state: lines, cursor, load/save, edit and movement operations. Knows nothing about the terminal, and nothing about any *other* buffer — each open file is a fully independent instance.
- =src/Dired.zig= — all directory-browser state: the current path, the entry list, the selection, and navigation (open, reload, move, go to parent, choose). Knows nothing about the terminal or about buffers, the same split as =Buffer.zig=.
- =src/main.zig= — the only platform-facing file: sets up the terminal via vaxis, runs the event loop, maps keys to =Buffer= calls, renders.

Keeping that split matters: it's the same portability discipline MicroEmacs used in the 1980s to run unmodified across CP/M, MS-DOS, VMS and Unix. Everything except =main.zig='s terminal setup should port to any future front end (a different TUI library, or eventually a GUI) unchanged.

Open buffers live in =main.zig= as =std.ArrayList(*Buffer)= — a list of *pointers* to individually heap-allocated buffers, not a list of buffers by value. That's deliberate: appending to the list (opening a new file) can reallocate the list's own backing array, which would silently invalidate a plain =*Buffer= pointer taken from it earlier. A pointer to an independently allocated =Buffer= stays valid regardless of what the list around it does. The kill ring is the one piece of state that lives above the buffer list entirely, shared by every buffer, matching real Emacs.

* Known caveat

Quitting (=C-x C-c=) relies on libvaxis's normal shutdown path, which sends a terminal status query to wake up its background input thread — real terminal emulators answer this automatically. This worked correctly for every editing and saving operation I tested through a real pseudo-terminal, but I could not fully confirm the exit path from inside a sandboxed test harness that lacks a real terminal emulator. If it ever seems to hang on quit in your actual terminal (unexpected — flag it if so), closing the terminal window or =C-c= from another shell will always work as a fallback.

* Roadmap

1. +*Kill ring + yank*+ — done (=C-space=, =C-k=, =C-w=, =M-w=, =C-y=). =Buffer.mark= is a plain snapshot, not a self-adjusting marker, so it can go stale if you edit the buffer between setting mark and using the region — acceptable for now, worth revisiting if it bites you.
2. +*Undo*+ — done (=C-x u=), whole-buffer snapshots with same-kind coalescing. Adding redo would mean pushing undone states onto a second stack that gets cleared on any new edit — a natural follow-up, not done yet.
3. +*Incremental search*+ — done (=C-s= / =C-r=). Search never crosses a line boundary and wraps around the buffer when it runs off either end. The =isearch_active= branch at the top of the key-dispatch loop in =main.zig= is the "mode" plumbing mentioned above — when =M-x= arrives, it's a second branch of the same shape, not a redesign.
4. +Unsaved-changes confirmation on =C-x C-c=+ — done. A save that fails (disk full, permissions, etc.) is still silently swallowed either way, same as =C-x C-s= today — worth real error reporting eventually.
5. +*Multiple buffers*+ — done (=C-x b=, =C-x C-f=). Every open buffer is its own heap-allocated =Buffer=; only the kill ring is shared. No way to close one yet (=C-x k=), so buffers only accumulate for the life of the process — fine for now, worth adding once it's annoying.
6. +*Directory browser (dired)*+ — done (=C-x d=). =src/Dired.zig= holds all directory state with no knowledge of the terminal or of buffers, the same split as =Buffer.zig=; =main.zig= just wires keys and rendering. =n= / =p= move, =^= goes to the parent, Enter opens a file (reusing the =C-x b= / =C-x C-f= open-or-switch path) or descends into a directory, =C-g= / =q= leaves. Entries sort with =..= first then case-insensitive; directories and files are interleaved (not grouped) and directories get a trailing =/=. =Dired.parentOf= doesn't canonicalise — once =dirname= can't go further up a relative path it just accumulates literal =..= components, which the OS resolves fine; it returns null only at the absolute filesystem root.
7. Config: start with a plain keymap-override file, consider embedded Lua later if you want real elisp-like programmability.
