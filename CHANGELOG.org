This document contains the release notes for james.

* Versions

** 0.31.0 — <2026-08-05>

Page scroll on =M-J= / =M-L=.

- =M-J= scrolls a page down and =M-K= a page up — the author's Emacs habit, where his config binds =M-J= to full-page =scroll-up= and =M-K= to =scroll-down=: the cursor moves one screenful (the focused window's text height minus its modeline), with the view following — in file buffers and in dired, where the selection jumps a listing page. =M-j= / =M-k= keep their 5-line moves.

** 0.30.0 — <2026-08-05>

The bookmark prompts stay in the window.

- Setting a bookmark (=C-x r m=) and the jump prompt (=C-x r b=) no longer take over the whole screen: the =Bookmark name (C-g cancels): ...= / =Jump to bookmark (C-g cancels): ...= prompt now appears in the focused window's own modeline, like the find-file, isearch and dired prompts — a split layout stays intact while you type the name, and Enter confirms without the view ever changing. (The bookmark picker =C-x r l= and the other full-screen modes are unaffected.)

** 0.29.0 — <2026-08-05>

Redo.

- Redo now works: =C-g C-/= (the author's Emacs habit) or =M-/= restores the state the last undo discarded — an undone edit comes back, cursor, mark, and modified flag included, and the redo is itself undoable (=C-/= undoes it again). Each undo pushes the state it discards onto a per-buffer redo stack; any new edit clears the stack, like Emacs abandoning the redo branch once you type after undoing. =C-/= alone still undoes — only a =C-/= pressed right after =C-g= redoes.

** 0.28.0 — <2026-08-05>

New tabs open on the current buffer.

- =M-l == now opens a new tab as a single window on the buffer the cursor is in — the point's buffer — instead of the scratch buffer, so a second tab continues the work in view rather than starting from a blank scratch. (Tabs still share the buffer list without per-tab association, so the two tabs show the same buffer like any other split would.)

** 0.27.0 — <2026-08-05>

The welcome screen's version line shows the build time.

- The version line under the welcome message now pairs the release date with the time the binary was built — =james 0.27.0 (2026-08-05 14:30) — The welcome screen's version line shows the build time.=, say — baked in by =build.zig= at compile time (UTC, like every timestamp james shows), so rebuilding the same version is visible at a glance on the home screen.

** 0.26.0 — <2026-08-05>

=M-w= copies a line with its newline.

- =M-w= with no mark set now copies the current line **including its trailing newline** (the buffer's last line has none), so pasting the line restores the line break — copying a line from a file and yanking it produces a full line, not text glued to whatever follows the paste point, matching Emacs's line copy. Consecutive line copies still join cleanly on the kill ring: the join rule adds a newline separator only when neither side has one, so a line ending in =\\n= appended to an earlier kill stays properly separated.

** 0.25.0 — <2026-08-05>

The selected dired entry is highlighted.

- Marked entries in dired are now highlighted: the whole row of a marked entry shows in reverse video, on top of the =*= in column 0 (the mark column) — the monochrome equivalent of Emacs's highlighted marks. General navigation is unchanged: the selected entry's row stays bold, like the cursor's line in a file buffer. An isearch match on a highlighted row drops the reverse (plain bold) so it stays distinct; matches elsewhere remain reverse video.

** 0.24.0 — <2026-08-05>

Tabs render at tab stops.

- Tab characters now display as spaces up to the next tab stop — every 4 columns, matching the author's Emacs =tab-width=: vaxis drops a raw tab byte (it measures 0 wide), so the fields of tab-separated text like the bookmarks file (=e= in the picker) used to glue together. The expansion happens at render time, so the buffer keeps its real tabs and files save byte-for-byte; the wrap, cursor, and highlight math all count tabs at their stops, so soft-wrapped tabbed lines, visual-line navigation, and isearch highlights stay in place. The expansions are freed after each frame renders.

** 0.23.0 — <2026-08-05>

Bookmarks persist on Windows.

- Bookmarks are now saved and loaded from the home directory the way Windows actually spells it: =%USERPROFILE%\.james-bookmarks= on Windows (falling back to =$HOME=, like the =M-l= jump keys), =~/.james-bookmarks= elsewhere — previously =saveBookmarks= and =loadBookmarks= both looked up =$HOME= directly, which Windows consoles almost never set, so on Windows no bookmark was ever saved or loaded (both calls bailed out silently).

** 0.22.0 — <2026-08-05>

=e= opens a bookmark's file from the top.

- The bookmark picker (=C-x r l= / =C-c o=) gains =e=: open the bookmarks file itself for editing — the plain text file james keeps the bookmark list in (=name<TAB>path<TAB>row<TAB>col= per line, =~/.james-bookmarks= / =%USERPROFILE%\.james-bookmarks=) — so the list can be reviewed or hand-edited directly. Saving that buffer (C-x C-s or =C-w=) reloads the in-memory bookmark list from the file immediately, so hand edits take effect at once instead of being overwritten by james's exit-time save of the stale list. The picker's modeline lists the new key.

** 0.21.0 — <2026-08-05>

The welcome screen shows the latest release.

- The home screen now shows a version line right under the welcome message, naming the latest version, its release date, and the most recent change — =james 0.21.0 (2026-08-05) — The welcome screen shows the latest release.=, say. The line is baked into the binary at build time from =CHANGELOG.org= — the version, date, and the change line under the top heading, with the org =...= markup stripped — so it appears however james is launched: from a terminal in the source tree or from the =james.desktop= launcher, whose working directory is =$HOME= rather than the source tree (the first cut read the file at startup, so the desktop launch silently skipped the line). It sits near the top of the screen, visible however short the terminal is.

** 0.20.0 — <2026-08-05>

isearch in the pickers.

- The buffer picker (=C-x b=) and the bookmark picker (=C-x r l= / =C-c o=) now support incremental search, like isearch in a dired: =C-s= / =C-r= starts it, typing extends the query and the selection jumps to the first match, =C-s= / =C-r= step through the matches (wrapping around the list), Backspace shrinks the query (restoring the original selection when it empties), Enter / =C-j= / =C-m= / Escape confirms with the match still selected — so the picker's own Enter then jumps or switches to it — and =C-g= cancels back to where the search started. The matched part of the row is highlighted in reverse video, the modeline shows the same =I-search: ...= / =Failing I-search= prompt as a buffer search, and the search runs over a bookmark's name or a buffer's display name (falling back to its file path).

** 0.19.0 — <2026-08-05>

=C-m= opens a dired entry.

- =C-m= now opens the selected dired entry (or descends into a directory), like Enter — the dired branch of the key dispatch was the one confirm spot that still lacked the =C-m= alias, so terminals that report Return as =C-m= through the kitty keyboard protocol (and the Windows console, which always sends =C-m= for Enter) could not open a file in dired. =C-m= now confirms everywhere Enter does, as the 0.13.0 release notes already claimed.

** 0.18.0 — <2026-08-05>

=C-x k= kills the current buffer.

- =C-x k= now kills (closes) the current buffer, like Emacs =kill-buffer= — a file buffer, a dired (the same close as =q= / =C-g= there), or the home screen. A modified file buffer asks first: the modeline reads =Save file <name> before killing?=, with =y= saving and killing, =n= killing without saving, and =C-g= / Escape cancelling (a save that fails keeps the buffer and reports =Save failed= on the modeline). The last buffer is never killed — the editor always keeps something on screen — and every window that showed the killed buffer falls back to the next one, the same fix-up the dired close already used. =C-x k= closes a dired directly, since dired buffers are never dirty.

** 0.17.0 — <2026-08-05>

=g= refreshes a dired.

- =g= in a dired buffer re-reads the directory listing (Emacs =revert-buffer= / =dired-revert=), keeping the selection where it was: the same =refresh= path the copy, delete, rename and create commands already use, now on its own key, so a listing changed outside james (a file added or removed in another terminal) is pulled back in without reopening the buffer. Marks are cleared by the refresh, as the post-copy/delete refresh already does.

** 0.16.0 — <2026-08-05>

Find-file prompts in the current window's modeline.

- =C-x C-f= no longer takes over the screen: the find-file prompt now appears in the focused window's own modeline (the prompt reads =Find file:=, matching Emacs), so a split window layout stays intact while you type the path. The prompt is ordinary modeline text — Backspace edits the path, Enter opens or switches to it (a directory path opens a dired), and =C-g= / Escape cancels — the same in-pane shape as the isearch and dired prompts.
- =C-x C-f= now prefills with the current buffer's directory, like Emacs's =find-file=: a file buffer's directory, or the directory being browsed while in a dired — always absolute, ending in a separator, so typing a bare file name opens it right there. The prefill is ordinary prompt text, so Backspace edits the directory like any other part of the path.
- Backspace now deletes the marked region when a mark is set (Emacs =delete-active-region=), saving it to the kill ring so =C-y= gets it back; with no mark it deletes one char backward as before.
- =M-w= now copies the current line when no mark is set, instead of doing nothing; with a mark set it copies the region as before.
- =M-f= / =M-b= move forward / backward by word (Emacs =forward-word= / =backward-word=): a word is a run of letters, digits, or underscore; punctuation and whitespace are skipped separately, so =M-f= from =foo.bar= lands on =.= then past =bar=. Word motion crosses line boundaries (a line break counts as non-word, like Emacs treating a newline as whitespace), but a word itself never spans a line break.
- =M-d= (and =C-delete=) kills one word forward (Emacs =kill-word=): kills from point to the end of the word run forward, saving the text to the kill ring so =C-y= gets it back; a following kill appends, like =C-k=. The mark is left untouched. (Emacs's numeric prefix argument is not supported — james has no prefix-arg system.)
- =M-Backspace= kills one word backward (Emacs =backward-kill-word=): the mirror of =M-d=, killing from point back to the start of the word run, saving the text to the kill ring so =C-y= gets it back; a following kill appends, like =C-k=. The mark is left untouched.

** 0.15.0 — <2026-08-05>

Dired shows the full directory path.

- A dired listing now starts with the directory's full path on its first line (the classic dired header line), and the modeline shows the same absolute path (=Dired: <path>=) instead of the raw browse path. The path is made absolute against the working directory, with =.= and =..= components resolved lexically (the display twin of Emacs's =expand-file-name= — no filesystem access, so symlinks are not resolved), so a dired opened as =C-x d= on =.= reads as the real directory. The header row is skipped when a pane is too small to spare one, and scrolling (=scrollToSelected=, the =C-l= recenter) counts the header row, so the selection never hides under it.

** 0.14.0 — <2026-08-03>

The my-jump keymap: =M-l= is now a prefix key, like the author's Emacs setup.

- =M-l= is a prefix keymap (the my-jump-keymap from the author's Emacs init.el): =M-l b= jumps to =~/bin=, =M-l d= to the Downloads directory, =M-l g= to the config directory, =M-l h= to the home directory, =M-l i= to =~/.emacs.d/Emacs-vanilla=, =M-l y= to =~/.emacs.d/Emacs-DIYer=, =M-l s= to =~/source=, =M-l o= opens the bookmark picker (bookmark-jump), and =M-l r= switches to the scratch buffer (=scratch.txt=, created if missing). =C-g= / Esc cancels the prefix; any other key is ignored, like an undefined binding in a real keymap.
- The directory targets resolve like the original elisp's =system-type= checks: on Windows =M-l d= uses =%USERPROFILE%\Downloads= (falling back to =~/Downloads=), =M-l g= uses =%APPDATA%= (falling back to =~/AppData/Roaming=), and =M-l h= uses =%USERPROFILE%=; elsewhere they are =~/Downloads=, =~/.config= and =~= respectively (home is =$HOME= on Unix, =%USERPROFILE%= on Windows).
- A jump that can't be opened (a missing =~/bin=, say) leaves the window alone instead of dropping the editor, and every jump is recorded in the winner-mode window history, so =C-c j= steps back out of it. The keys with no james equivalent were left out: =M-l == and =M-l -= (tabs), =M-l e= (the Emacs init.el), and =M-l l= (recentf — no recent-files tracking yet).
- =W= in a dired buffer opens the selected entry with the system's default handler — =xdg-open= on Linux/BSD, =open= on macOS, and cmd's =start= on Windows — so a file opens in its default application and a directory in the file manager, all without leaving the editor. The opener's stdio is thrown away so the terminal stays clean, and a failure (no =xdg-open=, no desktop session) reports on the modeline. =..= is skipped like =C= and =D=.
- Quitting (=C-x C-c=) no longer hangs on terminals that don't answer vaxis's device-status-report: the input thread is no longer awaited on the exit path (it's killed when the process exits), so =vx.deinit()= and =tty.deinit()= always run and the terminal is always restored. The =C-x j= shell-swap still awaits the thread — it needs the thread dead before handing the tty to a shell.
- When james is launched from a =james.desktop= file (=Terminal=true=), quitting no longer leaves a blank terminal window behind: the parent shell that ran james is sent SIGHUP on exit (gated by =JAMES_KILL_PARENT_ON_EXIT=1=, set in the .desktop Exec line via =env=), so the terminal closes with the editor. An interactive =james= from your own shell is unaffected — the env var is the opt-in, and only the .desktop launch sets it.
- Copy in dired (=C=) now defaults to the directory of another dired window when more than one window shows a dired (Emacs =dired-dwim-target=): the prompt pre-fills the other window's path, so a two-window setup — source dired on one side, destination on the other — copies the selected entry across windows with =C= then Enter, whichever side holds the cursor. The destination dired refreshes so the copied entry appears there immediately.
- =R= in dired renames (moves) the selected entry instead of copying it (Emacs =dired-do-rename=): the same dwim-target prompt as =C=, but Enter moves the entry across windows — a plain atomic rename, falling back to copy + delete across filesystems (where rename can't work).
- =+= in dired creates a directory and =_= creates an empty file in the current directory (the =+= is Emacs =dired-create-directory=): type the name on the modeline prompt (relative names resolve against the dired's path, absolute ones against the root; =+= makes nested paths too), Enter creates it, and the selection lands on the new entry. =_= never clobbers an existing file.
- Dired marking (Emacs =dired-mark= / =dired-unmark= / =dired-unmark-all-marks=): =m= marks the entry under the cursor and steps down (a run of =m='s marks a block), =u= unmarks one, =U= unmarks everything; marked entries show a =*= in column 0. =C= (copy) and =R= (rename/move) then apply to every marked entry at once — the prompt pre-fills just the target directory (the other dired window's, when there is one) and each entry keeps its own name there. With nothing marked, =C= / =R= operate on the selected entry alone, as before.
- =t= in dired toggles marks (Emacs =dired-toggle-marks=): with nothing marked it marks every file and directory; with a partial or full set it inverts the marks (=..= is never marked). =D= (delete) now also applies to every marked entry — the confirmation counts them (``Delete N entries?``) — and still defaults to the selected entry alone when nothing is marked.
- Tabs (a numbered tab set in the spirit of Emacs =tab-bar-mode=, without per-tab buffer association): =M-l == opens a new tab at the right end of the set, =M-l -= closes the current one, and =M-1=..=M-9= selects a tab by number. Each tab is an independent window layout over the shared buffer list — a new tab starts as a single window on the scratch buffer. The tab bar, one numbered block per tab (the active one highlighted), appears at the top of the screen only once a second tab exists. Window history does not cross tabs.
- Tab bar fixes: =M-i= / =M-u= step to the next / previous tab (wrapping), the tab set is capped at 16 tabs (the bar gives each tab its own label buffer), and each tab block now shows its own number — the previous bar shared one scratch buffer, so vaxis's grapheme slices (kept until the frame is drawn) made every block show the last tab's number.
- On Windows the kill ring and the system clipboard now sync through the native Win32 clipboard API instead of OSC 52: =C-y= with an empty kill ring reads the clipboard directly (the console's OSC 52 support is spotty — the legacy console ignores it and Windows Terminal gates it behind settings), so text copied in other applications shows up in james's kill ring, and kills and copies in james are written to the clipboard so other applications can paste them. Unix keeps the OSC 52 path, which works even over ssh.
- On Windows =C-y= now consults the real clipboard on every yank, not just when the kill ring is empty: the first paste remembered the clipboard text on the kill ring, so later copies from other applications were shadowed by the stale kill-ring head (james pasted the first clipboard copy again and again). An external copy that differs from the current kill-ring head now wins over it, like Emacs consulting the interprogram clipboard; only identical content falls through to a normal kill-ring yank.
- The line the cursor is on is now rendered bold — in file buffers and in dired, where the selected entry's whole row is bold — so your position is obvious while navigating even where the block cursor is hard to see. An isearch match or mark region on that line merges with the bold instead of replacing it.
- Visual-line navigation for soft-wrapped lines (Emacs visual-line-mode): =C-n= / =C-p= now step one visual line at a time, so a long wrapped paragraph is walked through line by line instead of only moving at its end; =C-a= and =C-e= move to the start and end of the visual line — on a wrapped segment =C-e= lands on its last character, since the wrap point itself displays at the start of the next visual line. Wrapped lines now also lay out on screen without clobbering the next line (each takes all of its visual rows), scrolling and =C-l= recentering follow the visual lines, and the cursor sits on the correct wrapped row and column. Movement, rendering, scrolling and the cursor all share one wrap calculation, so they always agree.

** 0.13.0 — <2026-08-03>

Buffer-list picker for =C-x b=.

- =C-x b= now shows a picker list of every open buffer — file buffers, direds, and the home screen — one per row, the same shape as the bookmark list: n/p (or arrows) move, Enter switches to the selected buffer, q / =C-g= closes. The cursor starts on the current buffer. =C-x C-f= keeps the old status-line prompt (open-or-switch by path), so typing a name to open a new file still works — the same C-x b / C-x C-f split real Emacs makes.
- Split windows now get a thin box-drawing line between them: a vertical =│= in the one-column gap of a side-by-side (vertical) split, and a horizontal =─= in a new one-row gap of a stacked (horizontal) split — which previously had no gap at all, so its panes butted against each other. Each line spans its own split's rect, so nested splits meet in clean T-junctions.
- A plain =zig build= now produces a ReleaseSmall, stripped binary instead of an unstripped debug build (the default optimize mode changed from Debug to ReleaseSmall, and stripping is on by default); =zig build -Doptimize=Debug -Dstrip=false= brings the old behaviour back. =./build.sh= passes =ReleaseSmall= for every preset, and cross-compile presets install to =zig-out/<target>/= so they no longer clobber the native binary in =zig-out/bin/=.
- Window sizing no longer depends on the terminal delivering its resize notification: the screen is now sized from the kernel's ioctl before the first frame, and re-verified against it on every event. A missed SIGWINCH or a dropped in-band size report used to leave the editor stuck at a fraction of the console's width (e.g. two thirds, if the console was wider than the terminal's last report) until a lucky resize — the resize anchor catches it on the very next keystroke.
- Terminal-size watchdog: a background thread re-reads the kernel's ioctl size every 100ms and posts a resize when it changed, so the editor now tracks the terminal even with no input at all. This fixes font-size zoom (foot/alacritty-style =C-= / =C--= rescale the grid without a reliable resize notification): previously the editor stayed at the old dimensions, looking shrunk with gaps to the right and bottom until the next keystroke. (A signal-handler timer was tried first but deadlocked on the event queue's mutex; a thread posts events the same way the input thread does.)
- =C-x j= (or =C-x c=) drops out of the editor into a real shell: the alternate screen is left and the terminal restored to its normal mode, then =$SHELL= (or =/bin/sh=) takes over the whole screen — full-screen programs included. =exit= / =C-d= returns to the editor, as does =C-z=, which only suspends the shell and is resumed by the next =C-x j= / =C-x c= with its state intact. The Windows build now supports it too: the console is returned to its normal mode and codepage, the shell (=$SHELL=, =COMSPEC=, or =cmd.exe=) runs, and =exit= returns — there is no =C-z= suspend on the Windows console.
- A failed save now shows =Save failed= in the modeline instead of failing silently (it is cleared on the next keypress); a bare =zig build -Dtarget=...= cross-compile now refuses to overwrite the native binary in =zig-out/bin= unless given =-p= (this had silently clobbered the native build three times); and =C-m= now confirms everywhere Enter does (switch-buffer, bookmark prompts and pickers, dired open, isearch, newline), for terminals that report C-m through the kitty keyboard protocol.
- The kill ring is now a real ring instead of a flat buffer: each kill or copy is a separate heap-allocated entry (bounded at sixty, oldest falling off), consecutive kills join with a newline when neither side has one (=abc= then =def= yanks as =abc\ndef=, not =abcdef=), and =M-y= (yank-pop) replaces the previous yank with the next older entry, all within the original yank's undo step. A clipboard paste heads the ring too, so it's immediately yankable.
- =M-w= now drops the mark after copying the region, like =C-c w= — the selection highlight clears instead of lingering.
- =C-l= recenters the window on the cursor line like Emacs recenter-top-bottom, within the focused pane of a split; it works in dired listings too. The position cycles middle → top → bottom only while =C-l= is pressed back to back; any other key — navigation included — resets the next =C-l= to the middle.
- The bookmark picker now shows each bookmark's base directory (dimmed, after the name; a dired bookmark shows its own directory), and =C-m= selects the bookmark like Enter — including terminals that report C-m through the kitty keyboard protocol as a modified key.
- =M-'= is now an alias for =M-q=: delete the current window (the window-delete key from the Jasspa setup).
- System clipboard integration via OSC 52: every kill or copy (=C-k=, =C-w=, =M-w=, =C-c b=, =C-c w=, =C-x C-k=) is mirrored onto the system clipboard, so text can be pasted into any other application (over ssh too — the terminal forwards the sequence). =C-y= with an empty kill ring requests the clipboard and pastes it into the buffer, like Emacs consulting the interprogram clipboard when the kill ring is empty. Terminals without OSC 52 support silently ignore the sequences.
- Starting with no files now opens a three-pane default layout: the welcome screen left (full height), a =scratch.txt= buffer top right, and a dired of the current directory bottom right. =scratch.txt= is a real file in the current directory — created on first startup if missing, opened without truncation if it exists — so it saves and prompts like any other buffer. A read-only directory falls back to the plain single-window home screen.
- =C-w= now saves the buffer (an alias of =C-x C-s=); kill-region lives at =C-x C-k= instead.
- Dired sorts on the digit keys, matching the ls flags (and the author's Emacs dired bindings): =3= by size (largest first), =4= by modification time (newest first), =5= by name, =6= by extension, and =s= toggles between name and date (dired-sort-toggle-or-edit). The selection moves to the first real entry, ".." stays pinned first, and the chosen order persists across refreshes. Entries carry their raw size and mtime for this (no parsing the formatted metadata back out).

** 0.12.0 — <2026-08-02>

Bookmarks.

- =C-x r m= bookmarks the current file and cursor position under a name; the prompt is prefilled with the file name (like Emacs), and setting an existing name replaces it. =C-x r b= prompts for a name and jumps: the file (or dired) opens and point moves to the recorded position. =C-x r l= (or =C-c o=, the "favorites" key from the Jasspa setup) shows all bookmarks in a picker (n/p move, Enter jumps, q / C-g closes).
- Bookmarks persist across sessions in =~/.james-bookmarks= (tab-separated =name/path/row/col= lines), saved on every set and on exit, loaded at startup.
- Dired bookmarks work too: jumping restores the selection to the recorded entry.
- Fixed garbled dired panes in multi-window splits: each pane now gets its own modeline scratch slot (the tree's slot arithmetic collided for small trees, so panes shared buffers), and dired entry labels print the entries' own heap names instead of a stack scratch copy — vaxis stores grapheme slices, so the previous stack buffer was clobbered by whichever pane rendered last, leaving every dired pane except the final ones garbled.
- isearch no longer takes over the whole screen: it operates inside the pane being searched, so splits keep their layout while searching. The searched pane shows the match highlight and the =I-search:= prompt in its own modeline, exactly like the full-screen view; dired panes show the prompt too (the match is the selected entry).
- Fixed two isearch-in-split bugs: the match highlight is now applied only to the focused pane (previously every pane rendered the match, so a dired search lit up a neighbouring file pane and could slice past a shorter line in it — an out-of-bounds crash); the highlight range is also clamped to the line defensively.
- =C-j= is now an alias for =C-m= (Enter) everywhere: it inserts a new line while editing, opens the selected entry in dired, and confirms the switch-buffer, bookmark, and search prompts.
- Dired now shows full =ls -al= style listings: each entry is prefixed with permissions (Unix rwx bits, including setuid/setgid/sticky; Windows shows read-only vs writable), a right-aligned size, and the modification timestamp. Metadata is computed once at load time into a heap string per entry (so rendering stays scratch-free) and symlinks are stat'd as links, not followed. All of it uses std's cross-platform =Io.File.Stat= — verified to compile for =x86_64-windows=, =x86_64-linux-musl=, and =aarch64-macos= (the std helper for Windows read-only-ness is broken in Zig 0.16, so the attribute bit is checked directly).
- Line highlights narrowed: the mark region and the isearch match keep their reverse-video highlight, and the current window's modeline is highlighted (a reverse bar spanning the pane, unfocused modelines dim) so it's obvious which window is active; the dired selection is plain — the blinking block cursor marks it there.
- In dired the block cursor now sits at the start of the entry's name, just after the metadata prefix, instead of at the start of the line.
- isearch in dired now highlights the matched part of the entry's name in reverse video, like the file-buffer match highlight.
- isearch is now always case-insensitive (ASCII), both forward and backward — the Jasspa "exact" mode being off.
- A modified buffer now shows an asterisk in the bottom-left corner of the modeline (Emacs-style), in both the pane and single-window modelines.
- Undo now restores the modified state too: each undo snapshot records the dirty flag, so undoing back to the saved state clears the asterisk (and the save-on-exit prompt), while undoing past an edit restores it.
- Full navigation in dired: =M-<= and =M->= jump to the first / last entry, and =M-j= / =M-k= move the selection 5 entries at a time (the cursor follows).
- Copy and delete in dired: =C= copies the selected entry to a target (prompt prefilled with the name; relative targets land in the current directory; copying a file onto itself or a directory into itself is refused), =D= deletes it after a y/n confirmation. Both refresh the listing in place (selection preserved) and re-mirror it for isearch.
- Copying a directory recursively copies its whole tree into a new directory (std's copyFile panics on directories, so this goes through a small recursive walk); the prompt reads "Copy directory <name> to". Deleting a directory recursively removes its tree (deleteTree), confirmed with "Recursively delete <name>?".
- The copy and delete prompts are in-pane, like isearch: the prompt text appears in the dired pane's modeline and the window layout never changes.
- Winner-mode style window history: =C-c j= steps back through previous window layouts and =C-c k= steps forward again. Every layout change (splits, deletes, collapses, resizes, switching which buffer a pane shows) is recorded first, so the whole pane tree, the buffers in each pane, and the focused pane are restored exactly; a new change abandons the redo branch.
- Fixed =M-e= getting stuck around the root of the filesystem: the dired "go up" handler and the file-buffer "dired-jump" handler both fired on the same keypress, and at =/= (where dirname is null) dired-jump fell back to =.=, bouncing the view between =.= and =..= forever. The dired-jump branch is now skipped for dired buffers (which the "go up" branch already handles).

** 0.11.0 — <2026-08-02>

Dired as a buffer.

- Dired is no longer a modal directory/file picker: a dired is an ordinary buffer, the default Emacs way. Each directory browsed is its own buffer (its =filename= is the directory path), so several can be open at once, they appear in the =(current/total)= count, =C-x b= switches to them by path (and a directory path typed into the prompt opens a fresh dired), and =C-x o= moves between windows freely — dired never blocks anything.
- Descending into a directory (=Enter= / =f=) opens a new dired buffer for it and the previous one stays open; =^= / =M-e= switches to the parent's dired buffer if one exists, else opens it. Opening a file shows it in the window and leaves the dired buffer open.
- =q= / =C-g= / =C-c C-k= close the current dired buffer (the window then shows the buffer that took its place), like Emacs's =dired-kill-buffer=.
- Dired buffers are read-only: typing and editing keys are ignored, while every =C-x= / =C-s= / =C-g= command still works on them. =Dired.choose= now just reports a path instead of mutating itself, so the buffer model lives entirely in =main.zig=.
- Fixed a crash opening a file from dired with Enter or =f=: the read-only guard was evaluated after the open had already switched =current= mid-keypress, so the same key fell through into the editing dispatch against the stale zero-line dired buffer (=insertNewline= indexed out of bounds). The guard is now captured before the dired keys run.
- Incremental search works in dired: the listing is mirrored into the dired buffer's lines (names, with =/= for directories), so =C-s= / =C-r= search the file names with the usual highlight and =I-search= prompt, the selection follows the match, and Enter after confirming opens the found file. Prompt modes (isearch, buffer switch, quit confirm) now render a dired through the normal buffer renderer, which also makes the =C-x b= prompt visible on a dired instead of being hidden behind the dired modeline.

** 0.10.0 — <2026-08-02>

Jasspa MicroEmacs keybindings.

- New bindings mirroring the =meuser.emf= setup, layered on top of the existing Emacs-style ones without rebinding anything: =C-/= undoes (also =C-x u=), =C-;= toggles a line comment (marker guessed from the file extension: =#= for Python/shell/org, =//= otherwise), =C-c b= copies the whole buffer, =C-c w= copies the region and deselects, =C-x C-k= kills the region, =C-x h= selects the whole buffer, =C-x g= re-reads the file from disk, and =C-x m= opens dired (alias of =C-x d=).
- Window movement aliases: =M-m= and =M-;= split (horizontally / vertically, matching the =C-x 2= / =C-x 3= directions) and switch to the new window, =M-n= / =M-p= move to the next / previous window, =M-q= deletes the current window, =M-a= collapses back to a single window (=C-x 1=).
- =M-<= / =M->= jump to the beginning / end of the buffer, =M-j= / =M-k= move 5 lines down / up, and =M-e= inside dired goes up a directory (alias of =^=); =C-c C-k= closes dired.
- =M-e= is now a full =dired-jump-or-up=: in dired it goes up a directory, and in a file buffer it opens dired rooted at that file's directory (matching the =my/dired-jump-or-up= binding in the Emacs config).
- In dired, =f= now opens the selected entry (the =dirlst-find-file= key from the Jasspa setup), the same as Enter.
- Window resizing: =M-C-h= / =M-C-l= shrink / enlarge the focused window's width, =M-C-k= / =M-C-j= its depth. Splits now carry a divider ratio (256ths) instead of always halving, and resize the nearest matching divider. Alt+Ctrl chords need a terminal that speaks the kitty keyboard protocol; elsewhere they simply don't fire.
- New =Buffer= methods behind it all: =moveBufStart= / =moveBufEnd= / =moveLines= / =toggleComment= / =copyWholeBuffer= / =reread=.
- =C-g= now also deselects a marked region: in the prompt modes it already cancels (quit confirmation, dired, buffer switch, search), and in normal editing it drops the mark so the reverse-video region highlight clears.
- The modeline is now a bar spanning the full window width, like Emacs's mode line: reverse video in the current window, dimmed reverse in the others, in splits and in the single-window view alike. (The bar is one segment built in a buffer that outlives the frame — vaxis stores grapheme slices, not copies, so an earlier stack-local fill buffer rendered garbage at the pane edge. The unfocused bars are dimmed /and/ reversed so they stay visible on terminals that ignore =dim= alone.)
- vaxis's own =std.log= output (the "(vaxis): kitty keyboard capability" startup notices) is suppressed via =std_options= — stderr shares the terminal, so that chatter used to be painted on the editor screen.

** 0.8.0 — <2026-08-01>

Nested window splits.

- =C-x 2= and =C-x 3= now split the focused pane instead of appending to a flat strip: =C-x 2= splits horizontally (panes stacked above / below), =C-x 3= vertically (panes side-by-side). Because each split subdivides the focused pane, directions nest freely — a vertical split inside a horizontal one, and so on, same as real Emacs.
- The split model is a binary tree of panes (the =Pane= struct in =main.zig=) rather than a flat list of buffer indices with one global split direction; each node divides its children either horizontally or vertically and the tree is rendered recursively into child windows.
- =C-x o= moves focus to the next pane, wrapping around; =C-x 0= deletes the focused pane, giving the space to its sibling; =C-x 1= collapses back to a single pane.
- Each pane keeps its own buffer; opening a file from =C-x b= / =C-x d= replaces only the focused pane's buffer. Panes draw their own compact modeline, and only the focused one shows the cursor.
- =C-x d= dired now renders inside the focused pane rather than taking over the whole screen, so any other split panes stay visible while browsing; choosing a file swaps dired for the newly opened buffer and the standard layout is restored.
- Splits are capped at 16 panes; further split requests are ignored.

** 0.7.0 — <2026-07-31>

Directory browser (dired).

- =C-x d= opens a directory listing in the editing pane, rooted at the directory of the current buffer's file (or =.= if the buffer has no file). It's another "mode branch" at the top of the key-dispatch loop in =main.zig= — the same shape as incremental search, the buffer-switch prompt, and the quit-confirmation, not a redesign.
- While in dired: =n= / =C-n= / ↓ and =p= / =C-p= / ↑ move the selection, =^= goes straight to the parent directory (the =^= shortcut in real dired), Enter descends into a directory or opens the selected file as a buffer, and =C-g= / =q= leaves dired and returns to the buffer.
- Opening a file from dired reuses the same open-or-switch path as =C-x b= / =C-x C-f=: if a buffer already visits that exact path it's switched to, otherwise the file is loaded fresh as a new buffer.
- Entries are sorted with =..= first, then case-insensitive by name; directories and files are interleaved rather than grouped, and directories are shown with a trailing =/=. Hidden (dot) files are listed too.
- =src/Dired.zig= holds all directory state (path, entries, selection, scroll, navigation) with no knowledge of the terminal or of buffers — the same portability split as =Buffer.zig=; =main.zig= just wires keys and rendering.
- =Dired.parentOf= doesn't resolve to a canonical absolute path: once a plain =dirname= can't go further up a relative path, further "up" requests just accumulate literal =..= components, which the OS resolves fine. It returns null only at the absolute filesystem root, where there's genuinely nowhere to go.

** 0.6.0 — <2026-07-27>

Multiple buffers.

- =C-x b= and =C-x C-f= both prompt for a filename on the status line and do the same thing: Enter switches to it if already open (matched by exact path, whitespace-trimmed), or loads and opens it fresh otherwise. =C-g= / Escape cancels.
- A single "open or switch by path" command covers both cases for a minimal editor, where real Emacs splits these (=C-x C-f= opens by path, =C-x b= switches by buffer name with separate completion).
- When more than one buffer is open, the status line shows =(current/total)= so it's visible at a glance.
- Every open buffer is its own heap-allocated =Buffer= stored in =main.zig= as =std.ArrayList(*Buffer)= — a list of pointers, not values, so appending (opening a new file) can't invalidate earlier pointers when the list's backing array reallocates.
- Only the kill ring lives above the buffer list, shared by every buffer, matching real Emacs.
- No way to close a buffer yet (=C-x k= in real Emacs) — buffers accumulate for the life of the process; a natural next step.

** 0.5.0 — <2026-07-27>

Unsaved-changes confirmation on quit.

- =C-x C-c= asks "Save file ... before exiting?" on the status line when the buffer has unsaved changes: =y= saves and quits, =n= quits without saving, =C-g= (or Escape) cancels the quit and returns to editing.
- Any other key is ignored while the prompt is up, rather than risk a stray keystroke accidentally choosing for you.
- A save that fails (disk full, permissions, etc.) is still silently swallowed, same as =C-x C-s= today — worth real error reporting eventually.
- Known caveat: quitting relies on libvaxis's normal shutdown path, which sends a terminal status query to wake its background input thread; real terminal emulators answer this automatically, but the exit path could not be fully confirmed from inside a sandboxed test harness lacking a real terminal emulator. Closing the terminal window or =C-c= from another shell always works as a fallback.

** 0.4.0 — <2026-07-27>

Incremental search.

- =C-s= / =C-r= for incremental search forward / backward.
- While searching: typing extends the query, =C-s= / =C-r= again jumps to the next / previous match, Backspace shrinks the query, =C-g= cancels back to the start, and Enter (or any other key) confirms and leaves the cursor at the match.
- A search with no match shows "Failing I-search" and stops moving the cursor until the query is backspaced back to something that matches.
- Search never crosses a line boundary and wraps around the buffer when it runs off either end.
- The =isearch_active= branch at the top of the key-dispatch loop in =main.zig= is the "mode" plumbing — when =M-x= arrives, it will be a second branch of the same shape, not a redesign.

** 0.3.0 — <2026-07-27>

Undo.

- =C-x u= restores whole-buffer snapshots taken before each edit.
- Coalesces a run of the same kind of edit (a burst of typing, a run of backspaces) into a single undo step, so undoing a word just typed is one keypress, not one per character.
- Switching to a different kind of edit — or moving the cursor — starts a new undo step.
- No redo yet: undo is a one-way trip back through history, and it does not (yet) clear the =[modified]= flag even if it lands back on the exact text loaded.
- Undo history, the mark, cursor position, and the dirty flag are all separate per buffer; only the kill ring is shared.

** 0.2.0 — <2026-07-27>

Kill ring and yank.

- =C-space= sets the mark; the region between mark and point is shown in reverse video as the cursor moves, and clears on kill, copy, or dropping the mark.
- =C-k= kills to end of line (or kills the newline at end of line); =C-w= kills the region (point to mark); =M-w= copies the region without deleting; =C-y= yanks the most recent kill.
- Consecutive =C-k= / =C-w= / =M-w= presses append to the same kill instead of overwriting it, same as real Emacs; typing or moving the cursor starts a fresh kill.
- The kill ring is shared across all open buffers, so text killed in one file can be yanked into another.
- =Buffer.mark= is a plain snapshot, not a self-adjusting marker, so it can go stale if the buffer is edited between setting mark and using the region — acceptable for now.

** 0.1.0 — <2026-07-27>

Initial release.

- A very minimal, Emacs/MicroEmacs-inspired text editor written in Zig on top of [[https://github.com/rockorager/libvaxis][libvaxis]].
- Basic cursor movement: =C-f= / =C-b= / =C-n= / =C-p= and arrow keys for right / left / down / up, =C-a= / =C-e= for start / end of line.
- Editing: =C-d= / Delete deletes forward, Backspace deletes backward, Enter inserts a new line.
- Save and quit: =C-x C-s= saves, =C-x C-c= quits.
- Each filename on the command line opens as its own buffer; the first is shown initially. First run fetches libvaxis automatically; =zig build --fetch= pre-fetches dependencies for offline builds.
- Cross-compiles with no extra toolchains or Docker: confirmed working on =x86_64-windows=, =aarch64-macos=, =x86_64-linux-musl=, and native with =-Doptimize=ReleaseSmall=; binaries land in =zig-out/bin/=.
- Architecture split: =src/Buffer.zig= holds all text state (lines, cursor, load/save, edit and movement operations) with no knowledge of the terminal or other buffers; =src/main.zig= is the only platform-facing file (terminal setup, event loop, key dispatch, rendering) — the same portability discipline MicroEmacs used in the 1980s.
- Requires Zig 0.16.0 exactly, pinned in =build.zig.zon=.
